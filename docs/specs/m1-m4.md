# Spec: core commands of M1, M3 and M4 (`merge`, `bench`, `closure`, `export`, `links`, `done`)

Status: draft. Milestones of DESIGN §11. Decisions: see docs/DECISIONS.md. Shared
conventions (envelope, exit codes, vault discovery, link resolution, path and note
arguments) are those of `docs/specs/m0.md` (§8 for arguments).

## 1. `loci merge <from> <into> [--dry-run]` (M1)

`--dry-run` plans and checks the merge, then reports it (`data.dry_run`: true, and
in the human form each edit and the deletion) and writes nothing.

Merges concept `<from>` into concept `<into>` after the agent has moved `<from>`'s
content into `<into>`. Both arguments are concept paths or bare slugs. The tool does the
bookkeeping; the content merge is the agent's work.

Refuses (exit 1, no writes) if either is not a concept (`note.kind`)
or they are the same note (`merge.same`), or the post-merge check fails
(`merge.verify`). Edits to one file that overlap or fall outside it, which a valid plan never makes,
are `change.edit` (exit 3). Otherwise, in one plan checked like `mv`
(m0 §9.5 step 3):

1. Every link whose target resolves to `<from>` is rewritten to `<into>`, keeping its
   form (bare slug or path), fragment, label and size. `prereqs` entries naming
   `<from>` are rewritten too; an entry that would name `<into>` inside `<into>`
   itself is removed.
2. `<from>` is deleted. Its slug is not kept: a name worth keeping goes into
   `<into>`'s text as part of the content merge.

A fragment that pointed into `<from>` keeps its text and may now dangle; `loci lint`
reports it (`link.dangling-heading`, `link.dangling-block`). `data`:
`{"from", "into", "edited": [{"path", "edits"}], "dry_run"}`.

## 2. `loci closure <concept> [--depth N]` (M3)

The prerequisite closure of a concept (a concept path or bare slug), over the
`prereqs` of concept notes in the working tree.

- Output: every concept reachable through `prereqs`, each once, in an order where a
  concept comes after all of its prerequisites (prerequisites first; ties by slug
  bytes), excluding the concept itself, with its depth (the shortest number of
  `prereqs` steps from the concept).
- `--depth N` keeps concepts at depth ≤ N.
- Prerequisite entries that do not resolve are listed under `unresolved` with the
  concept that names them. A cycle among the concepts kept (or back to the
  concept) gives one warning, `prereqs.cycle`, on the concept; the order breaks it by
  slug bytes, and `loci lint` names the cycle.
- An unknown note is `note.unknown`, one that is not a concept `note.kind` (exit 1).
- `data`: `{"concept", "closure": [{"slug", "path", "depth"}], "unresolved":
  [{"from", "target"}]}`. The human form lists `- [[slug]]` lines in order.

## 3. `loci bench <agent command> [--cases <file>]` (M1)

Runs an agent on benchmark cases and checks each result. The cases file is
`bench/cases.jsonl` in the vault, or `--cases <file>` (relative to the working
directory); one JSON object per line, `{"q": "<question or task>", "check": "<shell
command>"}`. loci measures only the agent, which searches and edits the vault itself
(searching with `rg`, as the framework rules say).

- Each case runs on a fresh copy of the vault in a temporary directory, without its
  `bench/` folder, so the agent never sees the cases and no case sees another's
  edits; the copy is deleted afterwards and the vault itself is never touched. The
  copy's `.git` is a repository of its own with the vault's history, HEAD and index,
  also when the vault is a linked worktree or a submodule (whose `.git` is a file
  naming a repository it shares), so the agent's commits stay in the copy.
- In the copy, `<agent command>` runs through `sh -c` with the question on stdin and
  a 600-second timeout; its stdout is read on its own thread and written to a file
  outside the copy, and its stderr goes to loci's. Then `check` runs through `sh -c` in the
  copy, with `LOCI_BENCH_OUTPUT` naming that file; the case passes if the check
  exits 0. A check reads the reply (`grep -q '\[\[stack' "$LOCI_BENCH_OUTPUT"`) or
  the vault the agent left (`test -f concepts/a/x.md && loci lint`). A case that
  times out fails. The agent's own token or tool counts are not read.
- Failing to copy the vault or to start `sh` is `bench.agent` (exit 3). A malformed
  line is `bench.case` (exit 1, naming the line). A missing file, or one with no
  cases, is `bench.none` (exit 1).
- `data`: `{"cases", "pass_rate", "median_s", "results": [{"q", "pass",
  "agent_exit"}]}`, where `median_s` is the median wall time per case and
  `agent_exit` the agent's exit code (`null` when it timed out or was killed by a
  signal); a case's pass is its check's alone. The human form is one line:
  `N cases: pass rate P, median S s`.

## 4. `loci export <view-or-concept> [--depth N] [--to md|html] [-o <path>]` (M4)

Writes one self-contained document from a view (`views/...`) or a concept (path or
slug). Default `--depth 1`, `--to md`, output `.loci/export/<stem>.<ext>` (inside the
gitignored `.loci/`, so lint never sees it) unless `-o` is given (relative to the
working directory).

1. **Collect.** The root note, then the targets of its wikilinks and embeds that are
   notes, in order of first appearance, then (up to `--depth`) the notes those link
   to. Each note is included once, at its first appearance, and that link decides
   the part included: a `[[x#heading]]` link includes only that heading's section
   (the heading through the next heading of the same or a higher level);
   `[[x#^id]]` includes only that block; any other link, the whole note.
2. **Assemble** markdown: the root note's body, then each included part under a
   heading one level below the heading level at which it is linked (the root's own
   headings unchanged), with its own headings shifted to fit and capped at level 6.
   A part that does not start with a heading gets one inserted, with the note's
   title (m0 §4.7). A setext heading is written as an ATX one, its text on one line
   (m0 §4.6; a hard break's backslash stays). A heading written without closing `#`s
   of its own (an inserted title, a setext heading, an ATX heading written without)
   whose text, with its links rewritten (step 3), ends in a `#` run that ATX would read
   as closing gets a closing ` #`, so it reads back whole. Frontmatter is stripped, and each
   block id (`^id`) with the whitespace before it. Where that would change the shape
   of the note's blocks (their kinds, nesting, heading levels and item counts: a line
   left as `===` reads as a heading underline, `***` as a rule), the `^id` becomes an
   empty HTML comment `<!-- -->` instead.
3. **Links.** A wikilink's text is its label, else the heading its fragment names,
   else the linked note's title. A wikilink to an included note becomes a markdown
   link (`[text](#anchor)`) to the heading it names when that heading was included,
   else to the top heading of the note's part. An anchor is the heading text by
   GitHub's rule (lowercased; letters, digits, `-` and `_` kept; each space a `-`;
   anything else dropped; `section` if nothing is left), with `-1`, `-2`, … appended
   when taken earlier in the document, so the links of a markdown export also work
   where GitHub renders it. A wikilink to a note that is not included becomes its text, plain;
   one that does not resolve, its label or its target as written.
   A label, title or heading is markdown and goes in as written; a target, file path
   or image file name is literal and goes in with a backslash before each ASCII
   punctuation character (CommonMark §2.4).
4. **Images.** Every embedded image is copied to `<output dir>/assets/` (name
   collisions get a numeric suffix) and becomes `![alt](assets/<name>)`, the name
   percent-encoded (every byte but `A-Z a-z 0-9 - . _ ~` as `%XX`, RFC 3986), so the
   link names that file also where a browser loads it.
5. **Formats.** `md` is the assembled markdown. `html` is a standalone page rendered
   by loci itself (`pulldown-cmark`: tables, footnotes, task lists, strikethrough),
   each heading given the identifier its links use, and math rendered to MathML
   (`pulldown-latex`), which browsers display natively; TeX it cannot render is shown
   in red with the error. The page loads nothing from the network. For a PDF, print
   the page from a browser. An internal failure to render is `export.html` (exit 3).

Refuses an unknown target (`note.unknown`) or a target that is not a view or
concept (`note.kind`). The default output is written as vault files are: a symlink on
the way into `.loci/export/` is refused (`file.symlink`, m0 §3). `data`: `{"output", "notes": [paths], "assets": [paths]}`.

## 5. `loci links <note>`

Lists the links of a note and the links that point at it. `<note>` is a note
argument (m0 §8) or the vault path of any other file (an image, a source file).

- **Outgoing:** every link in the note, in file order: wikilinks, embeds and
  `prereqs` entries. Each has its line, form (`wiki`, `embed`, `prereq`), raw text,
  and target: the note or file it resolves to (fragment ignored), or `null` when it
  does not resolve. A file that is not a note has no outgoing links.
- **Incoming:** every link in any note whose target is the note or file, with a
  fragment or not, in note path order, then file order.
- **Unlinked mentions**, both ways (for a note). A name of a note is its title, the
  title without its parenthesised parts, each parenthesised name (`# Breadth-first
  search (BFS)`), or its file name without `.md` read as words (a concept's slug).
  ASCII case is folded and `-` matches a space; a Latin name must stand as whole
  words (`graph` is not found in `paragraph`); text inside wikilinks and embeds does
  not count.
  - *Of the note:* every formed note (concept, area file, view, journal entry) that
    names it without linking it, with the line of the first mention; notes that
    already link it are left out. These are the missing links into it (step 4 of
    adding a concept in the framework rules).
  - *In the note:* every concept the note names without linking it, with the words
    of the first mention, in text order; concepts it already links are left out, and
    a mention inside a longer one ("queue" in "priority queue") does not count.
    These are the missing links out of it (step 3).
- An unknown target is `note.unknown` (exit 1); an ambiguous slug is
  `concept.ambiguous`.
- `data`: `{"note", "outgoing": [{"line", "form", "raw", "target"}], "incoming":
  [{"path", "line", "form", "raw"}], "unlinked_in": [{"path", "line", "text"}],
  "unlinked_out": [{"line", "text", "concept"}]}`. The human form lists `line: raw ->
  target` under `links from <note>:`, `path:line: raw` under `links to <note>:` (a
  `prereqs` entry ends with ` (prereq)` in both), `path:line: <line text>` under
  `unlinked mentions of <note>:`, and `line: <words> -> [[<slug>]]` under `unlinked
  mentions in <note>:`.

## 6. `loci done [--note <text>]...`

The last step of every agent task (framework rules, "Workflow"). It runs `loci lint`
(same output, diagnostics and exit code), then records the agent's work:

- **Record.** The working tree, ignoring gitignored files, becomes a commit whose
  parent is `HEAD`, stored as `refs/loci/agent/<HEAD commit id>`. It is built in a
  private index, so the user's index, branches and files are untouched. Author and
  committer are `loci <loci@localhost>`, dated now, unsigned. A later `loci done`
  on the same `HEAD` replaces the ref: one record per starting commit.
- **Notes.** Each `--note` is something the agent found hard in the task (a search
  that missed, an unclear rule, work a command could do). Notes go into the
  record's commit message after the first line, `loci done: the agent's work`, one
  `- <note>` line each, with whitespace collapsed. A later run on the same `HEAD`
  keeps the notes of the record it replaces and adds new ones, once each. The
  `improve` skill reads them as hypotheses.
- **Nothing to record.** When the tree equals `HEAD`'s and there are no notes, no
  ref is written. Without `HEAD` none is either, and that is warning `done.record`
  (commit once first).
- **Pruning.** Records older than 90 days are deleted.
- **Failure.** A git failure while recording is warning `done.record`, and while
  pruning warning `done.prune`; the lint result stands.
- Refs under `refs/loci/` are not pushed by `git push` or `git push --all`, only by
  `--mirror` or a configured refspec, and are not copied by `git clone`.
- `data`: the `loci lint` data plus `"record": <ref or null>`.

The user never runs `loci done` for their own work: a record taken after the user's
corrections would count them as the agent's.
